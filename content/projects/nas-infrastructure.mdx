This was for a small business client that couldn't justify managed cloud hosting for every
service or keep an infrastructure engineer on hand. So the setup had to keep running with very
little maintenance, and be easy to understand for whoever looks after it after me.

I built the whole stack (redundant file storage, remote access for staff and WordPress hosting)
on a single Synology NAS instead of rented servers.

## Storage and redundancy

I set the NAS up with a RAID volume so a single failed disk doesn't lose the business's files,
and configured file shares with different access levels, some open to everyone and others
limited to specific staff roles, with Synology DSM handling the permissions.

For remote access I used Synology's QuickConnect with a VPN, so staff can reach shared files from
outside the office without the NAS management interface being exposed to the internet.

## Hosting and reverse proxy

The same NAS also hosts the websites. The WordPress sites run behind Synology's built-in reverse
proxy, which handles HTTPS with Let's Encrypt certificates and routes traffic to the right site by
domain name, so several sites share one public IP.

Each domain points at the NAS's public IP through DNS at the registrar, and Let's Encrypt's
automatic renewal keeps SSL working without anyone needing to renew it manually.

## Design decisions

The main decision was putting everything on the NAS instead of splitting file storage and web
hosting between the NAS and a separate VPS. One box is cheaper and simpler, but it ties the two
together: a disk failure during a RAID rebuild would affect both. I explained that trade-off to
the client, and for their workload and risk tolerance one box made sense.

The other was using WordPress for every public site. It isn't the fastest option, but
non-technical staff can update it without needing a developer, which mattered more here.

## What I learned

This covered DNS, TLS, the reverse proxy, file-share permissions, remote access and application
hosting. None of those are hard individually. Most of the work was getting them to work together
and keeping the setup simple enough for someone else to maintain.
