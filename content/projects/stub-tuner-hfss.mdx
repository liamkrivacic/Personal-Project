A plasma load's impedance changes as the operating conditions change, and a fixed-tuned
waveguide circuit can't follow it. When the match drifts, reflected power goes up, efficiency
drops and the magnetron takes more stress. A three-stub tuner fixes this by adjusting the line
impedance, but it has three stub depths to set, and finding the right combination by hand means
searching a three-dimensional space one slow simulation at a time. That isn't practical during
live operation.

So I automated it. I wrote an IronPython script that runs inside ANSYS HFSS as a gradient-descent
loop: move the stubs slightly, check the reflected power, step in the direction that lowers it,
and repeat. It runs unattended against a simulated plasma load.

<Callout title="Key result (simulated)">
In one test case the script pulled the load reflection coefficient from roughly **0.88 down to
0.25** across **20 automated tuning steps**, with no human in the loop. These are HFSS simulation
results, not measurements on a live system.
</Callout>

## Choosing an approach

Before writing any code I had to decide what the loop would measure. There were two options.

**Method 1: phase-based direct computation.** An AD8302 gain/phase detector reads both the
magnitude and phase of the reflected signal relative to the incident wave. With the full complex
reflection coefficient at every step, you can solve for the stub positions directly from the
impedance-transformation equations, without searching or iterating.

**Method 2: gradient search on reflected power only.** A log power detector reads one value,
reflected power. You move the stubs slightly, see which way the power changes, and step in the
direction that lowers it. There's no phase measurement.

I went with the gradient search. Method 1 works well on paper, but it needs accurate phase data,
which means a known reference plane right at the plasma face and careful AD8302 calibration. Both
are hard to get right on a real installation. The gradient approach only needs power, so it's
simpler to instrument and much less sensitive to cable-length and reference errors. The downside
is more simulation steps per tuning cycle, which is fine for an automated loop.

## Why a three-stub tuner

The three-stub tuner is the standard choice for high-power WR340 because it can handle kilowatt
power levels that would destroy a thin-film or ferrite matching network. Each stub is a
short-circuit plunger pushed into the broad wall of the waveguide, and how far it goes in sets the
susceptance at that point on the line. With three stubs spaced a quarter-wavelength apart, the
tuner can reach any load impedance within its range.

It also suited what we had. A four-probe reflectometer with full phase measurement would have
needed more instrumentation than AtomCraft had at the design stage, while the three-stub gradient
approach only needs a reflected power reading.

The tuner has since been manufactured. The photos show the three stubs going through the broad
wall into the guide.

## The gradient descent algorithm

The IronPython script controls HFSS through its COM scripting interface, setting stub depths and
reading reflected-power results back without any manual input. The loop is:

1. Simulate the current stub configuration and record reflected power.
2. Perturb each stub depth by a small step and re-simulate.
3. Estimate the gradient (change in reflected power per unit stub movement).
4. Move all three stubs in the direction of lower reflected power.
5. Repeat until the reflection coefficient falls below a target threshold or the step
   count is reached.

The tuning constant sets how big each step is. The simulation runs showed that if it's too high,
the algorithm overshoots the minimum and oscillates around it instead of settling, the same
problem as a learning rate that's too high. Before this loop runs on real hardware, the tuning
constant has to be calibrated to the sensitivity of each load profile.

## The reflected power landscape

Before running the optimiser on the full three-dimensional search, I wanted to know what the
reflected-power surface looks like. The clearest picture of it is from Chtcherbakov and Swart's
1997 automatic three-stub tuner for plasma deposition, which moves the stubs by steepest descent
on reflected power alone, the same method my script uses. Their measured contour map, with real
minimisation paths drawn over it, is the same kind of surface my script has to search:

The single minimum is what makes a gradient approach work. Because the surface has one minimum
instead of several, steepest descent ends up at the true match instead of getting stuck in a
local minimum, which is what the four paths show. If there had been several minima I would have
needed a different approach, so I checked this before building my own loop in HFSS.

## Convergence on the Smith chart

The easiest way to see the algorithm working is on a Smith chart, where the load reflection
coefficient traces a path through the normalised impedance plane as the loop runs. Starting from
a badly mismatched load near the edge, each tuning step moves the impedance closer to the centre,
where $|\Gamma| = 0$ and the match is perfect:

<Figure
  src="/projects/stub-tuner-hfss/smith-chart-300-180i.png"

  caption="Smith chart convergence for a 300+180j Ω load. Each dot is one tuning step. The trajectory moves from the chart edge (high reflection) toward the centre across 20 iterations, confirming the gradient is navigating correctly."

A smooth inward path like this means the step size and tuning constant suit the load. With a
higher tuning constant on the same load, the path circles the centre and oscillates instead of
reaching it, which is the overshoot problem described above.

The main thing I learned is that IronPython scripting can turn HFSS from a one-off solver into a
search loop, and a future automated matching system for AtomCraft would be built on the same
idea.

## Source code

<CodeBlock title="gradient-descent-v1.py - IronPython script for ANSYS HFSS">

```python
### Required setup ###
import ScriptEnv
ScriptEnv.Initialize("Ansoft.ElectronicsDesktop")
oDesktop.RestoreWindow()
import os

## Get S11 (dB) at the frequency closest to target_freq_hz from an HFSS design.
## mode=1 returns the S11 value; mode=0 returns the closest frequency.
def get_s11_or_frequency(oDesign, sweep_name, target_freq_hz, mode):
    oModule = oDesign.GetModule("ReportSetup")
    oResults = oModule.GetSolutionDataPerVariation(
        "Terminal Solution Data",
        sweep_name,
        ["Domain:=", "Sweep"],
        ["Freq:=", ["All"]],
        ["dB(St(1,1))"]
    )
    NominalData = oResults[0]
    SweepValues = NominalData.GetSweepValues("Freq", True)
    DataValues = NominalData.GetRealDataValues("dB(St(1,1))")
    closest_index = min(range(len(SweepValues)), key=lambda i: abs(SweepValues[i] - target_freq_hz))
    if mode == 1:
        return DataValues[closest_index]
    else:
        return SweepValues[closest_index]

## Set a local variable in the HFSS design (appends "mm" to numeric values).
def change_local_variable(oDesign, var_name, var_value):
    var_value_str = str(var_value) + "mm" if isinstance(var_value, (int, float)) else str(var_value)
    oDesign.ChangeProperty([
        "NAME:AllTabs",
        [
            "NAME:LocalVariableTab",
            ["NAME:PropServers", "LocalVariables"],
            ["NAME:ChangedProps", ["NAME:" + var_name, "Value:=", var_value_str]]
        ]
    ])

def create_report(oDesign):
    freq = get_s11_or_frequency(oDesign, "Setup1 : Sweep", TARGET_FREQ_HZ, 0)
    oModule = oDesign.GetModule("ReportSetup")
    oModule.CreateReport(
        "Tuning Chart", "Modal Solution Data", "Smith Chart", "Setup1 : Sweep", [],
        ["Freq:=", [freq],
         "a:=", ["Nominal"], "b:=", ["Nominal"], "l:=", ["Nominal"],
         "w:=", ["Nominal"], "f:=", ["Nominal"], "s:=", ["Nominal"],
         "d:=", ["Nominal"], "d1:=", ["All"], "d2:=", ["All"], "d3:=", ["All"]],
        ["Polar Component:=", ["S(1,1)"]]
    )

def update_report(oDesign):
    freq = get_s11_or_frequency(oDesign, "Setup1 : Sweep", TARGET_FREQ_HZ, 0)
    oModule = oDesign.GetModule("ReportSetup")
    oModule.UpdateTraces(
        "Tuning Chart", ["S(1,1)"], "Setup1 : Sweep", [],
        ["Freq:=", [freq],
         "a:=", ["Nominal"], "b:=", ["Nominal"], "l:=", ["Nominal"],
         "w:=", ["Nominal"], "f:=", ["Nominal"], "s:=", ["Nominal"],
         "d:=", ["Nominal"], "d1:=", ["All"], "d2:=", ["All"], "d3:=", ["All"]],
        ["Polar Component:=", ["S(1,1)"]]
    )

### Project setup ###
oProject = oDesktop.GetActiveProject()
oDesign = oProject.GetActiveDesign()
oModule = oDesign.GetModule("Solutions")

TARGET_FREQ_HZ = 2.45e9
SWEEP_NAME = "Setup2 : Sweep"
ITERATIONS = 20
SMALL_POSITION_CHANGE = 0.5   # mm: perturbation step for gradient estimation
STEP_SIZE_CONST = 3           # tuning aggressiveness; reduce if oscillation occurs

### Initialise all stubs at 0 mm insertion ###
d1_length = d2_length = d3_length = 0.0
change_local_variable(oDesign, "d1", d1_length)
change_local_variable(oDesign, "d2", d2_length)
change_local_variable(oDesign, "d3", d3_length)

### Gradient descent loop ###
for x in range(ITERATIONS):
    results_mag = []

    # Baseline S11 at current stub positions
    oDesign.Analyze("Setup1 : Sweep")
    results_mag.append(get_s11_or_frequency(oDesign, "Setup1 : Sweep", TARGET_FREQ_HZ, 1))

    if x == 0:
        create_report(oDesign)
    else:
        update_report(oDesign)

    # Perturb each stub in turn and record S11
    for var, length in [("d1", d1_length), ("d2", d2_length), ("d3", d3_length)]:
        new_length = max(0, min(43.2, length + SMALL_POSITION_CHANGE))
        change_local_variable(oDesign, var, new_length)
        oDesign.Analyze(SWEEP_NAME)
        results_mag.append(get_s11_or_frequency(oDesign, SWEEP_NAME, TARGET_FREQ_HZ, 1))

    # Estimate gradient (dS11/d_stub) for each stub
    results_grad = [
        (results_mag[1] - results_mag[0]) / SMALL_POSITION_CHANGE,
        (results_mag[2] - results_mag[1]) / SMALL_POSITION_CHANGE,
        (results_mag[3] - results_mag[2]) / SMALL_POSITION_CHANGE,
    ]

    # Normalised gradient step
    grad_magnitude = sum(g ** 2 for g in results_grad) ** 0.5
    step_size = STEP_SIZE_CONST / grad_magnitude

    # Move stubs in direction of decreasing S11
    d1_length = max(0, min(43.2, d1_length - SMALL_POSITION_CHANGE - step_size * results_grad[0]))
    d2_length = max(0, min(43.2, d2_length - SMALL_POSITION_CHANGE - step_size * results_grad[1]))
    d3_length = max(0, min(43.2, d3_length - SMALL_POSITION_CHANGE - step_size * results_grad[2]))

    change_local_variable(oDesign, "d1", d1_length)
    change_local_variable(oDesign, "d2", d2_length)
    change_local_variable(oDesign, "d3", d3_length)
```
